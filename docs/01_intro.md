# 第1章：ポートフォリオとは何か

## ポートフォリオの目的

ゲーム・クリエイター業界やWeb業界では、履歴書だけでなく「実際に作ったもの」で評価されます。  
ポートフォリオは **自分の技術力・発想力・問題解決力を見せるための作品集** です。

### 採用担当者が見ているポイント

| 観点 | 具体的に見ていること |
|------|---------------------|
| **技術力** | バージョン・何ができるか・深さ |
| **実績** | どんな規模のものを、どんな役割で作ったか |
| **プロセス** | なぜその実装を選んだか・詰まった問題をどう解決したか |
| **継続性** | 複数の作品があるか・GitHubが定期的に更新されているか |
| **自走力** | 個人で完成させた経験があるか |

---

## ポートフォリオに入れるべきセクション

このポートフォリオで実装するセクションと、それぞれの目的です。

| セクション | 目的 |
|-----------|------|
| **Hero** | 名前・職種・座右の銘で第一印象を作る |
| **About** | 自己紹介・学校・タイムラインで人柄を伝える |
| **Skills** | バージョン・できること・実装経験を具体的に示す |
| **Works** | 制作物の詳細（技術選定理由・詰まった問題・改善）を見せる |
| **Game Jams** | 学校外の活動・短期制作経験を示す |
| **Certifications** | 資格・実績・取得状況を整理して見せる |
| **Contact** | 採用担当者が連絡できる導線を作る |

### スキルの書き方について

「Unityが使えます」という記述だけでは採用担当者には何も伝わりません。  
実務で求められるのは「どのバージョンで」「何ができるか」という具体的な解像度です。

```
✗ 悪い例：Unity, C#, React

✓ 良い例：
  Unity 2022.3 LTS
  → 3D/2Dゲーム開発、Physics演算、ProceduralGeneration
  → プロシージャル迷宮生成・A*経路探索を個人作品で実装済み
```

---

## ポートフォリオ制作の注意点

- 未完成の作品を載せない（「制作中」でも完成物がない状態はNG）
- 学校の課題をそのまま提出しない（自分なりの工夫・改造を加える）
- 写真・UI素材・フォントの著作権に注意する
- GitHub リポジトリは `public` に設定する

---

## ReactとVue、どちらを使うか？

| | React | Vue |
|---|---|---|
| 構文 | JSX（JSの中にHTMLを書く） | SFC（.vue ファイルにまとめる） |
| 学習コスト | やや高め | やや低め |
| 採用需要 | 非常に高い | 高い |
| 向いている人 | JS強化したい・大規模開発 | 直感的に学びたい |

**どちらで作っても問題ありません。**  
まず1つを完成させることが最重要です。授業で学んだ方を選ぶのが最短です。
